## 3. Исправленный скрипт ETA

Для приведения кода в соответствие с контрактом было написано следующее решение:

```python
def eta(distance_m, speed_mps, delay_s, status):
    if status == "broken":
        return None
    if status == "blocked":
        return None
    if distance_m < 0:
        return None
    if distance_m == 0:
        return 0
    if speed_mps <= 0:
        return None
    return distance_m / speed_mps + delay_s
```
**Ручная трассировка (пример из отладчика):**
Вызов `eta(900, 4, 90, "moving")`.
Скрипт последовательно пропускает проверки статуса и расстояния, доходит до строки 12 и выполняет `return distance_m / speed_mps + delay_s`.  
Результат: 900 / 4 + 90 = 225 + 90 = 315 с.  
Автоматическая проверка стенда: **9 из 9 проверок пройдено**.

**Проверка граничных случаев (трассировка):**
- `eta(0, 0, 30, "moving")` → срабатывает условие `distance_m == 0`, возвращается `0` (трамвай на остановке).
- `eta(900, 0, 0, "moving")` → срабатывает условие `speed_mps <= 0`, возвращается `None` (скорость нулевая, прогноза нет).
- `eta(-900, 12, 0, "moving")` → срабатывает условие `distance_m < 0`, возвращается `None` (остановка позади).

## 4. Патч 1.5 и регрессия

При активации патча 1.5 и тех же условиях (T+0, остановка «Мост») была обнаружена регрессия.  
- У вагона 701 сырой знак направления остался **+1** (движение вправо), но знак пульта сменился на **−1**. Из-за этого координаты на пульте начали уменьшаться (на T+15 стало 1620 вместо 1980), а расстояние до остановки стало отрицательным (−1080). Наш скрипт ETA честно вернул `None`.
- У вагона 705, который уже проехал остановку, из-за инверсии знака расстояние стало положительным (595 м), и скрипт ошибочно выдал прогноз 54.09 с.
- Автоматическая проверка 1.5 показала **7 из 9**: математика ETA (первые 7) работает идеально, но проверки направления (последние 2) провалились. Это доказывает, что дефект находится в слое телеметрии пульта, а не в коде ETA.

**Таблица сравнения версий (регрессия):**

| Версия | Вагон | Сырые метры и знак T+0 → T+15 | Пульт: метры и знак T+0 → T+15 | Что видит пассажир |
| :--- | :--- | :--- | :--- | :--- |
| **1.4** | 701 | 1800 (+1) → 1980 (+1) | 1800 (+1) → 1980 (+1) | Приближается, 2 мин → 1 мин |
| **1.4** | 702 | 3420 (−1) → 3285 (−1) | 3420 (−1) → 3285 (−1) | Приближается, 2 мин → 1 мин |
| **1.5** | 701 | 1800 (+1) → 1980 (+1) | 1800 (−1) → 1620 (−1) | Исчез с табло (расстояние < 0) |
| **1.5** | 702 | 3420 (−1) → 3285 (−1) | 3420 (+1) → 3555 (+1) | Исчез с табло (расстояние < 0) |
| **После отката** | 701 и 702 | 1800 (+1) → 1980 (+1), 3420 (−1) → 3285 (−1) | 1800 (+1) → 1980 (+1), 3420 (−1) → 3285 (−1) | Снова приближаются, 2 мин → 1 мин |

**Цепочка регрессии:**  
Сырая телеметрия (знак +1) → обработка пультом 1.5 (знак инвертируется на −1) → расстояние для ETA становится отрицательным → функция возвращает `None` → табло скрывает вагон или показывает неверное время (как с 705).

## 7. Решение о выпуске

Патч 1.5 **не может быть выпущен** в текущем виде. Он содержит критическую регрессию в обработке телеметрии, которая инвертирует знак направления и приводит к ошибочным прогнозам (исчезновение реальных вагонов и появление прогноза для уехавших).

**Условия для повторной проверки 1.5:**  
Разработчикам необходимо исправить логику обработки знака направления в пульте (вернуть корректное умножение на `dir` вместо `-dir`). После исправления требуется повторно прогнать автоматические проверки (должно быть 9/9) и вручную проверить движение вагонов 701, 702 и 705 на обеих сторонах табло.

**Ограничения учебной модели:**  
Модель не учитывает реальные дорожные условия, динамику разгона/торможения и точное время стоянки. Прогноз ETA является линейным и не учитывает возможные изменения скорости на перегоне. В учебном интерпретаторе деление на ноль даёт `Infinity`, тогда как в реальном Python возникло бы исключение `ZeroDivisionError`.
